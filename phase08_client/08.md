# Phase 8 — MCP Client

## 1. Goal

Until now we've mainly built the server:

```text
MCP Server
    ↓
Tools
    ↓
Repository
    ↓
SQLite
```

Now we'll build:

```text
Python Client
      │
      │ MCP protocol
      ▼
MCP Server
      │
      ▼
Tools / Resources
      │
      ▼
Repository
      │
      ▼
SQLite
```

The client will:

1. Start the MCP server
2. Establish an MCP connection
3. Discover available tools
4. Discover resources
5. Call tools
6. Read resources
7. Handle errors
8. Close the connection cleanly

**No LLM yet.**

This is deliberate.

---

# 2. Why No LLM Yet?

Eventually we'll have:

```text
User
 ↓
LLM
 ↓
MCP Client
 ↓
MCP Server
```

But if we introduce the LLM immediately, there are too many moving parts.

Instead:

```text
Phase 8

Python
 ↓
MCP Client
 ↓
MCP Server
```

Then:

```text
Phase 9

Python
 ↓
LLM
 ↓
MCP Client
 ↓
MCP Server
```

This allows us to distinguish:

```text
MCP problem
```

from:

```text
LLM problem
```

# 4. MCP Client Architecture

The MCP client uses the MCP Python SDK.

Conceptually:

```text
┌─────────────────────────────┐
│        Python Client        │
│                             │
│  ClientSession              │
│       │                     │
│       ├── list_tools()      │
│       ├── call_tool()       │
│       ├── list_resources()  │
│       └── read_resource()   │
└──────────────┬──────────────┘
               │
               │ MCP
               ▼
┌──────────────────────────────┐
│         MCP Server           │
│                              │
│       FastMCP                │
│          │                   │
│          ▼                   │
│     Tools / Resources        │
└──────────────────────────────┘
```

# 5. Transport

For local development we'll use **stdio**.

That means:

```text
Python Client
     │
     │ stdin/stdout
     ▼
Python MCP Server
```

The client starts the server as a subprocess.

This is particularly useful for learning because there is no HTTP server, port, Docker container, or authentication infrastructure to configure yet.

---

# 6. `client.py`

Create:

```text
phase08_client/client.py
```

Start with:

```python
import asyncio
import sys
from pathlib import Path

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


SERVER_PATH = (
    Path(__file__).parent / "server.py"
)


async def main() -> None:

    server_parameters = StdioServerParameters(
        command=sys.executable,
        args=[str(SERVER_PATH)],
    )

    async with stdio_client(
        server_parameters
    ) as (read, write):

        async with ClientSession(
            read,
            write,
        ) as session:

            await session.initialize()

            print("Connected to MCP server")

            tools = await session.list_tools()

            print("\nAvailable tools:")

            for tool in tools.tools:
                print(
                    f"- {tool.name}: "
                    f"{tool.description}"
                )


if __name__ == "__main__":
    asyncio.run(main())
```

```text
Client                         Server

   initialize  ────────────────►

   ◄──────────── capabilities
```

# 10. Discovering Tools

This:

```python
tools = await session.list_tools()
```

asks the server:

```text
"What tools do you expose?"
```

The server responds with metadata.

For example:

```text
create_order
```

will have information describing:

```text
name
description
input schema
```

This is extremely important for LLM integration.

The LLM doesn't need your Python source code.

It can receive the tool definition.

# 12. This Is the Bridge to the LLM

This is one of the most important concepts in MCP.

Your Python function:

```python
@mcp.tool()
def create_order(
    customer_id: int,
    product: str,
    amount: float,
):
```

becomes a machine-readable tool definition.

Conceptually:

```text
Python function
       ↓
MCP tool definition
       ↓
JSON schema
       ↓
LLM
```

The LLM can now reason:

```text
"I need to create an order."

Available tool:

create_order(
    customer_id,
    product,
    amount
)
```

# 21. Create a Simple Interactive Client

Now make the client more useful.

Create:

```text
interactive_client.py
```

```python
import asyncio
import sys
from pathlib import Path

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


SERVER_PATH = Path(__file__).parent / "server.py"


async def main() -> None:

    server_parameters = StdioServerParameters(
        command=sys.executable,
        args=[str(SERVER_PATH)],
    )

    async with stdio_client(
        server_parameters
    ) as (read, write):

        async with ClientSession(
            read,
            write,
        ) as session:

            await session.initialize()

            tools = await session.list_tools()

            print("\nConnected to MCP server.")
            print("\nAvailable tools:")

            for tool in tools.tools:
                print(f"  {tool.name}")

            while True:

                print("\nCommands:")
                print("1. Find customer")
                print("2. Get customer")
                print("3. Create customer")
                print("4. Create order")
                print("5. Cancel order")
                print("6. Exit")

                choice = input("\nChoose: ").strip()

                if choice == "1":

                    name = input(
                        "Customer name: "
                    )

                    result = await session.call_tool(
                        "find_customer",
                        {
                            "name": name,
                        },
                    )

                    print(result)

                elif choice == "2":

                    customer_id = int(
                        input("Customer ID: ")
                    )

                    result = await session.call_tool(
                        "get_customer",
                        {
                            "customer_id": customer_id,
                        },
                    )

                    print(result)

                elif choice == "3":

                    name = input("Name: ")
                    email = input("Email: ")

                    result = await session.call_tool(
                        "create_customer",
                        {
                            "name": name,
                            "email": email,
                        },
                    )

                    print(result)

                elif choice == "4":

                    customer_id = int(
                        input("Customer ID: ")
                    )

                    product = input(
                        "Product: "
                    )

                    amount = float(
                        input("Amount: ")
                    )

                    result = await session.call_tool(
                        "create_order",
                        {
                            "customer_id": customer_id,
                            "product": product,
                            "amount": amount,
                        },
                    )

                    print(result)

                elif choice == "5":

                    order_id = int(
                        input("Order ID: ")
                    )

                    result = await session.call_tool(
                        "cancel_order",
                        {
                            "order_id": order_id,
                        },
                    )

                    print(result)

                elif choice == "6":

                    print("Goodbye.")
                    break

                else:

                    print("Unknown command.")


if __name__ == "__main__":
    asyncio.run(main())
```

# 26. Structured Results

Our tools currently return dictionaries.

For example:

```python
return {
    "success": True,
    "customer": {
        "id": customer.id,
        "name": customer.name,
        "email": customer.email,
    },
}
```

This is useful for an LLM because the result is structured.

Conceptually:

```text
Tool call
    ↓
structured result
    ↓
LLM
```

rather than:

```text
Tool call
    ↓
random human-readable paragraph
```

# 30. Phase 8 Key Concept

MCP is **not the LLM**.

Think of the components separately:

```text
              ┌──────────────┐
              │     LLM      │
              │              │
              │ GPT          │
              │ Claude       │
              │ Gemini       │
              │ Llama        │
              └──────┬───────┘
                     │
                     │ decides
                     │ which tool
                     ▼
              ┌──────────────┐
              │ MCP Client   │
              └──────┬───────┘
                     │
                     │ MCP
                     ▼
              ┌──────────────┐
              │ MCP Server   │
              └──────┬───────┘
                     │
                     ▼
                Application
```

The MCP server doesn't care whether the caller is:

```text
GPT
Claude
Gemini
Llama
a Python program
another application
```
