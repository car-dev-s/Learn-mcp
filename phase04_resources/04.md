## Phase 4 — MCP Resources

Phase 3 taught us **tools**. Phase 4 introduces the second major MCP primitive: **resources**.

The key distinction:

```text
Tool
    → the model/client asks the server to DO something

Resource
    → the client/application asks the server for DATA/CONTEXT
```

We'll keep the same customer domain and in-memory data. **No database and no LLM yet.**

# 2. What is an MCP Resource?

An MCP Resource represents data that can be made available through the MCP server.

A resource has a URI.

For example:

```text
customers://all
```

or:

```text
customers://1
```

The URI identifies the data.

Conceptually:

```text
customers://1
        │
        ▼
Customer #1
        │
        ▼
{
    "id": 1,
    "name": "John Smith",
    "email": "john@example.com"
}
```

---

# 3. Tool vs Resource

This distinction is extremely important.

## Tool

Suppose we have:

```text
get_customer(1)
```

The client is asking the server:

> Perform an operation and give me the result.

That's a **tool**.

```text
Client
  │
  │ call get_customer(1)
  ▼
Server
  │
  ▼
perform operation
  │
  ▼
result
```

---

## Resource

Now consider:

```text
customers://1
```

The client is asking:

> Give me the contents of this resource.

That's a **resource**.

```text
Client
  │
  │ read customers://1
  ▼
Server
  │
  ▼
resource contents
```

---

# 4. When should you use each?

A useful rule:

### Use a Tool when:

```text
The operation represents an action.
```

Examples:

```text
create_customer()
cancel_order()
send_email()
search_customer()
calculate_price()
```

### Use a Resource when:

```text
The thing represents data/context that can be read.
```

Examples:

```text
customers://all
customers://123
database://schema
config://application
docs://architecture
```

# 8. Implement the Server

Create:

```text
phase04_resources/server.py
```

Use:

```python
import json

from mcp.server.fastmcp import FastMCP

from data import customers, orders


mcp = FastMCP("customer-server")


# ============================================================
# Tools
# ============================================================

@mcp.tool()
def find_customer(name: str) -> list[dict]:
    """
    Find customers whose name contains the supplied text.

    The search is case-insensitive.
    Returns an empty list when no customers match.
    """

    search_text = name.strip().lower()

    if not search_text:
        return []

    matches = [
        customer
        for customer in customers
        if search_text in customer.name.lower()
    ]

    return [
        {
            "id": customer.id,
            "name": customer.name,
            "email": customer.email,
        }
        for customer in matches
    ]


@mcp.tool()
def get_customer(customer_id: int) -> dict | None:
    """
    Get a customer by its ID.

    Returns null when the customer does not exist.
    """

    for customer in customers:
        if customer.id == customer_id:
            return {
                "id": customer.id,
                "name": customer.name,
                "email": customer.email,
            }

    return None


@mcp.tool()
def get_orders(customer_id: int) -> list[dict]:
    """
    Get all orders belonging to a customer.

    Returns an empty list when the customer has no orders.
    """

    customer_orders = [
        order
        for order in orders
        if order.customer_id == customer_id
    ]

    return [
        {
            "id": order.id,
            "customer_id": order.customer_id,
            "product": order.product,
            "amount": order.amount,
            "status": order.status,
            "created_at": order.created_at.isoformat(),
        }
        for order in customer_orders
    ]


@mcp.tool()
def get_order(order_id: int) -> dict | None:
    """
    Get an order by its ID.

    Returns null when the order does not exist.
    """

    for order in orders:
        if order.id == order_id:
            return {
                "id": order.id,
                "customer_id": order.customer_id,
                "product": order.product,
                "amount": order.amount,
                "status": order.status,
                "created_at": order.created_at.isoformat(),
            }

    return None


# ============================================================
# Resources
# ============================================================

@mcp.resource("customers://all")
def get_all_customers() -> str:
    """
    Return all customers as JSON.
    """

    result = [
        {
            "id": customer.id,
            "name": customer.name,
            "email": customer.email,
        }
        for customer in customers
    ]

    return json.dumps(result, indent=2)


@mcp.resource("customers://{customer_id}")
def get_customer_resource(customer_id: int) -> str:
    """
    Return a single customer as JSON.
    """

    for customer in customers:
        if customer.id == customer_id:
            result = {
                "id": customer.id,
                "name": customer.name,
                "email": customer.email,
            }

            return json.dumps(result, indent=2)

    return json.dumps(
        {
            "error": "Customer not found",
            "customer_id": customer_id,
        },
        indent=2,
    )


if __name__ == "__main__":
    mcp.run()
```

# 9. What We Added

The important new code is:

```python
@mcp.resource("customers://all")
def get_all_customers() -> str:
```

and:

```python
@mcp.resource("customers://{customer_id}")
def get_customer_resource(customer_id: int) -> str:
```

The first is a fixed resource.

The second is a **parameterized resource**.

---

# 10. Fixed Resource

This:

```text
customers://all
```

always represents:

```text
all customers
```

Conceptually:

```text
customers://all
       │
       ▼
[
    Customer 1,
    Customer 2,
    Customer 3
]
```

---

# 11. Parameterized Resource

This:

```text
customers://{customer_id}
```

defines a resource template.

Therefore:

```text
customers://1
```

means:

```text
Customer 1
```

while:

```text
customers://2
```

means:

```text
Customer 2
```

and:

```text
customers://3
```

means:

```text
Customer 3
```

Conceptually:

```text
customers://{customer_id}
           │
           │
      ┌────┼────┐
      ▼    ▼    ▼
      1    2    3
      │    │    │
      ▼    ▼    ▼
     John Alice David
```

# 19. Important: Tool vs Resource

We now have two ways to get a customer.

### Tool

```text
get_customer(1)
```

### Resource

```text
customers://1
```

They look similar, but conceptually they serve different purposes.

### Tool

```text
get_customer(1)
```

means:

> Execute the `get_customer` operation with ID 1.

### Resource

```text
customers://1
```

means:

> Read the customer resource identified by this URI.

---

# 20. Why Not Make Everything a Tool?

You might ask:

> Why don't we just use `get_customer()` for everything?

Because MCP resources are useful for representing **addressable context/data**.

Imagine a larger system.

You could expose:

```text
customers://all
orders://all
schema://customer
schema://orders
docs://customer-api
config://application
```

These are pieces of context that an MCP client/application can retrieve.

They aren't necessarily actions.

---

# 21. Example: Database Schema Resource

Later, when we introduce SQLite, we could expose something like:

```text
database://schema
```

containing:

```text
customers
---------
id INTEGER
name TEXT
email TEXT

orders
------
id INTEGER
customer_id INTEGER
product TEXT
amount REAL
status TEXT
created_at TIMESTAMP
```

The client could read that resource as context.

The model doesn't need a tool like:

```text
get_database_schema()
```

if the schema is naturally represented as a resource.

# 22. Another Example: Documentation

Imagine an MCP server for your company's internal systems.

Resources could be:

```text
docs://authentication
docs://customer-api
docs://order-api
docs://troubleshooting
```

Tools could be:

```text
create_customer()
cancel_order()
reset_password()
```

Now the distinction becomes clearer:

```text
Resources
    ↓
Information/context

Tools
    ↓
Actions
```

---

# 23. Resource URI Design

Resources should have meaningful URIs.

Good:

```text
customers://all
customers://123
orders://123
docs://authentication
database://schema
```

Avoid meaningless URIs such as:

```text
data://x1
data://foo
resource://thing
```

The URI should help humans and clients understand what the resource represents.

# 24. Resource Output

We're returning JSON as a string:

```python
return json.dumps(result, indent=2)
```

This makes the resource easy to inspect.

For real applications, the resource contents might instead be:

```text
JSON
CSV
Markdown
XML
plain text
binary content
```

depending on what the resource represents.

---

# 25. One Important Architectural Point

Resources do **not** mean:

> "The LLM automatically sees all resources."

That's not necessarily the case.

The MCP host/client is responsible for deciding how resources are surfaced to the model/application.

Conceptually:

```text
MCP Server
    │
    ├── Tools
    │
    └── Resources
            │
            ▼
       MCP Client/Host
            │
            ▼
            LLM
```

The host may choose when and how resource contents are added to the model's context.

This is an important distinction from simply saying:

```text
Resource = context automatically injected into LLM
```

That is too simplistic.
