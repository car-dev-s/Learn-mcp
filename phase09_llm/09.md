# Phase 9 — LLM + MCP Client

## 1. Goal

In Phase 8 we had:

```text
Python Client
      │
      │ MCP
      ▼
MCP Server
      │
      ▼
SQLite
```

In Phase 9 we add an LLM:

```text
                    User
                      │
                      ▼
                     LLM
                      │
                 tool decision
                      │
                      ▼
                MCP Client
                      │
                      │ MCP
                      ▼
                MCP Server
                      │
                      ▼
                   SQLite
```

The LLM should be responsible for:

* understanding the user's request
* deciding whether a tool is needed
* selecting a tool
* generating tool arguments
* interpreting the tool result
* generating the final response

The MCP server remains responsible for:

* authorization
* validation
* business rules
* database access
* audit logging

# 8. The LLM Client

Create:

```text
phase09_llm/llm_client.py
```

```python
from openai import AsyncOpenAI

from config import (
    OPENAI_API_KEY,
    OPENAI_MODEL,
)


class LLMClient:

    def __init__(self) -> None:

        self.client = AsyncOpenAI(
            api_key=OPENAI_API_KEY
        )

        self.model = OPENAI_MODEL


    async def chat(
        self,
        messages: list[dict],
        tools: list[dict],
    ):

        response = await self.client.chat.completions.create(
            model=self.model,
            messages=messages,
            tools=tools,
            tool_choice="auto",
        )

        return response
```

This class knows about OpenAI.

It should know **nothing** about:

```text
SQLite
MCP
customers
orders
repositories
```

# 10. MCP Client Wrapper

Create:

```text
phase09_llm/mcp_client.py
```

```python
import sys
from pathlib import Path

from mcp import (
    ClientSession,
    StdioServerParameters,
)
from mcp.client.stdio import stdio_client


class MCPClient:

    def __init__(
        self,
        server_path: Path,
    ) -> None:

        self.server_path = server_path

        self._stdio_context = None
        self._session_context = None

        self.session = None


    async def connect(self) -> None:

        parameters = StdioServerParameters(
            command=sys.executable,
            args=[str(self.server_path)],
        )

        self._stdio_context = stdio_client(
            parameters
        )

        read, write = await self._stdio_context.__aenter__()

        self._session_context = ClientSession(
            read,
            write,
        )

        self.session = (
            await self._session_context.__aenter__()
        )

        await self.session.initialize()


    async def close(self) -> None:

        if self._session_context:
            await self._session_context.__aexit__(
                None,
                None,
                None,
            )

        if self._stdio_context:
            await self._stdio_context.__aexit__(
                None,
                None,
                None,
            )


    async def list_tools(self):

        return await self.session.list_tools()


    async def call_tool(
        self,
        name: str,
        arguments: dict,
    ):

        return await self.session.call_tool(
            name,
            arguments,
        )
```

This wraps the MCP SDK.

# 12. MCP Tool Definition

From Phase 8:

```python
tools = await session.list_tools()
```

A tool might contain:

```text
name:
create_order

description:
Create an order for a customer.

inputSchema:
{
    ...
}
```

OpenAI expects a tool definition with roughly:

```json
{
  "type": "function",
  "function": {
    "name": "create_order",
    "description": "Create an order for a customer.",
    "parameters": {
      "type": "object",
      "properties": {
        "customer_id": {
          "type": "integer"
        }
      }
    }
  }
}
```

We therefore convert MCP → LLM format.

---

# 13. Tool Conversion

Add to `mcp_client.py`:

```python
def convert_tools_for_openai(
    tools,
) -> list[dict]:

    result = []

    for tool in tools.tools:

        result.append(
            {
                "type": "function",
                "function": {
                    "name": tool.name,
                    "description": (
                        tool.description or ""
                    ),
                    "parameters": tool.inputSchema,
                },
            }
        )

    return result
```

Now:

```text
MCP
 ↓
tool metadata
 ↓
OpenAI format
 ↓
LLM
```

# 14. Main Application

Create:

```text
phase09_llm/main.py
```

```python
import asyncio
from pathlib import Path

from llm_client import LLMClient
from mcp_client import (
    MCPClient,
    convert_tools_for_openai,
)


SERVER_PATH = (
    Path(__file__).parent / "server.py"
)


async def main() -> None:

    mcp = MCPClient(
        SERVER_PATH
    )

    llm = LLMClient()

    await mcp.connect()

    try:

        tools = await mcp.list_tools()

        llm_tools = convert_tools_for_openai(
            tools
        )

        print("\nAvailable tools:")

        for tool in llm_tools:
            print(
                "-",
                tool["function"]["name"],
            )

        messages = [
            {
                "role": "system",
                "content": (
                    "You are a helpful customer "
                    "service assistant."
                ),
            }
        ]

        while True:

            user_input = input(
                "\nUser: "
            ).strip()

            if user_input.lower() in {
                "exit",
                "quit",
            }:
                break

            messages.append(
                {
                    "role": "user",
                    "content": user_input,
                }
            )

            response = await llm.chat(
                messages,
                llm_tools,
            )

            message = (
                response.choices[0].message
            )

            if message.content:
                print(
                    "\nAssistant:",
                    message.content,
                )

            messages.append(
                message.model_dump(
                    exclude_none=True
                )
            )

    finally:

        await mcp.close()


if __name__ == "__main__":
    asyncio.run(main())
```

# 15. There Is One More Problem

The code above can allow the LLM to **request** a tool.

But we still need to execute the tool.

The LLM may return:

```text
tool_calls:
    create_order
    arguments:
        customer_id=1
        product="Laptop"
        amount=1000
```

Our application needs to do:

```text
LLM
 ↓
tool call
 ↓
MCP Client
 ↓
MCP Server
```

# 16. Tool Execution Loop

Add this logic inside the main loop.

Replace the response handling with:

```python
response = await llm.chat(
    messages,
    llm_tools,
)

message = response.choices[0].message


if not message.tool_calls:

    print(
        "\nAssistant:",
        message.content,
    )

    messages.append(
        message.model_dump(
            exclude_none=True
        )
    )

    continue
```

Now process tool calls:

```python
for tool_call in message.tool_calls:

    tool_name = tool_call.function.name

    arguments = tool_call.function.arguments

    import json

    arguments = json.loads(arguments)

    print(
        f"\n[LLM requested tool: "
        f"{tool_name}]"
    )

    print(
        f"[Arguments: {arguments}]"
    )

    result = await mcp.call_tool(
        tool_name,
        arguments,
    )

    print(
        f"[MCP result: {result}]"
    )
```

# 17. But We Need to Give the Result Back

This is the most important part of the tool-calling loop.

The sequence is:

```text
User
 ↓
LLM
 ↓
"I need create_order"
 ↓
MCP Client
 ↓
create_order()
 ↓
MCP Server
 ↓
SQLite
 ↓
result
 ↓
MCP Client
 ↓
LLM
 ↓
final answer
```

The LLM needs to see the result.

# 18. Complete Tool Loop

Use:

```python
import json


response = await llm.chat(
    messages,
    llm_tools,
)

message = response.choices[0].message


if not message.tool_calls:

    print(
        "\nAssistant:",
        message.content,
    )

    messages.append(
        message.model_dump(
            exclude_none=True
        )
    )

    continue


messages.append(
    message.model_dump(
        exclude_none=True
    )
)


for tool_call in message.tool_calls:

    tool_name = tool_call.function.name

    arguments = json.loads(
        tool_call.function.arguments
    )

    print(
        f"\n[Tool requested: {tool_name}]"
    )

    print(
        f"[Arguments: {arguments}]"
    )

    result = await mcp.call_tool(
        tool_name,
        arguments,
    )

    print(
        f"[Tool result: {result}]"
    )

    messages.append(
        {
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": str(result),
        }
    )


# Ask the LLM to interpret the tool result

final_response = await llm.chat(
    messages,
    llm_tools,
)

final_message = (
    final_response.choices[0].message
)

print(
    "\nAssistant:",
    final_message.content,
)

messages.append(
    final_message.model_dump(
        exclude_none=True
    )
)
```

# 25. Very Important Security Rule

Never do this:

```python
if tool_name == "cancel_order":
    ...
```

and blindly execute whatever the LLM requests.

The server must remain authoritative.

Even if the model sends:

```json
{
  "customer_id": -100
}
```

or:

```json
{
  "amount": 999999999999
}
```

or:

```json
{
  "order_id": 999999999
}
```

the server validates it.

# 26. Add an Explicit Tool Allowlist

There's another useful defense.

In `main.py`:

```python
ALLOWED_TOOLS = {
    "find_customer",
    "get_customer",
    "get_orders",
    "get_order",
    "create_customer",
    "update_customer",
    "create_order",
    "cancel_order",
}
```

Before executing:

```python
if tool_name not in ALLOWED_TOOLS:

    raise RuntimeError(
        f"Tool '{tool_name}' is not allowed"
    )
```

This gives the client another security boundary.

Remember:

```text
Client allowlist
+
Server authorization
```

The server remains the final authority.

# 29. What Actually Changes Between Models?

This is the question you originally asked.

The MCP server:

```text
                  SAME
              MCP SERVER
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
       GPT      Claude    Gemini
        │         │         │
        └─────────┼─────────┘
                  ▼
                Llama
```

stays the same.

The differences are primarily in:

### 1. API client

GPT:

```text
OpenAI SDK
```

Claude:

```text
Anthropic SDK
```

Gemini:

```text
Google GenAI SDK
```

Llama:

```text
depends on deployment
```

---

### 2. Tool/function schema

The providers have different API formats for describing tools.

Our adapter handles that:

```text
MCP schema
    │
    ├── OpenAI adapter
    ├── Anthropic adapter
    ├── Gemini adapter
    └── Llama adapter
```

---

### 3. Tool-calling behavior

Models can differ in:

```text
Which tool they select
How they interpret descriptions
How accurately they generate arguments
Whether they call multiple tools
How they recover from errors
How much context they use
```

This is one of the things we'll test experimentally.

---

### 4. Model reasoning

For example:

```text
User:
"Find John's latest order and cancel it."
```

A model may need to perform:

```text
find_customer
      ↓
get_orders
      ↓
get_order
      ↓
cancel_order
```

Different models may produce different tool-call sequences.

The MCP server remains identical.

# 30. MCP Does Not Make Models Equal

This is important.

MCP standardizes the **tool/context interface**.

It does not standardize model intelligence.

For example:

```text
MCP
 ↓
same tools
```

doesn't guarantee:

```text
GPT == Claude == Gemini == Llama
```

They can still differ significantly in:

* tool selection
* argument generation
* multi-step planning
* instruction following
* context handling
* error recovery
* hallucination rate
* latency
* cost

# 32. Don't Evaluate Only the Final Answer

For MCP applications, inspect:

```text
                 Model
                   │
                   ▼
              Tool choice
                   │
                   ▼
              Arguments
                   │
                   ▼
             Tool sequence
                   │
                   ▼
              Tool result
                   │
                   ▼
             Final answer
```

A model can produce a convincing final answer while making a bad tool call.

For example:

```text
User:
Cancel order 123.
```

Model:

```text
cancel_order(321)
```

and then:

```text
"Order 123 has been cancelled."
```

That's a serious failure.
